    Key Performance Indicators (KPIs)

    This document defines the KPIs used to assess the performance and trustworthiness of the AI component, and the methodology to aggregate them into a single trust score.

    The methodology follows a multi-criteria aggregation pipeline, structured around 5 trust attributes covered here:

    1. Performance — predictive accuracy and operational cost
    2. Uncertainty — quality of confidence estimates
    3. Robustness — invariance to perturbations within the ODD
    4. OOD Monitoring — ability to flag inputs outside the ODD
    5. Generalization — stability across unseen weld types

    A 6th attribute, Data-Drift handling, is documented in the original challenge protocol but is deferred for this iteration of the TP — see § Deferred: Data-Drift handling.

    KPI Mapping to Lifecycle Phases

    Trust attribute Construction Training Evaluation Operation
    Performance X X
    Uncertainty X X
    Robustness X X
    OOD Monitoring X X
    Generalization X
    Data-Drift (deferred) X

    1. Performance

    Purpose: Measure the model's predictive accuracy and efficiency, ensuring it meets baseline expectations in a controlled setting.

    Evaluation set: Standard ML evaluation set — representative 20% split of the dataset.

    Metrics

    • OP-Perf (Operational Performance): confusion-matrix-based metric weighted by a non-symmetric cost matrix that penalizes errors according to weld criticality.
    OP = Σ_k Σ_i Σ_j 𝟙{Top_class(ŷ_k) = j} · cost(i, j, k, k_seam)

    Per-seam weights:

    Seam k_seam
    c102 0.2
    c20 0.4
    c33 0.4

    Cost matrix (asymmetric — false negatives heavily penalized):

    Predicted KO Predicted OK Predicted UNKNOWN
    True KO 26.4 3000 41
    True OK 30 0.4 20
    • ML-Perf: standard ML metric (precision / FBeta with β=1 since June 13).
    ML = Σ 𝟙(y=1 ∧ ŷ=1) / Σ 𝟙(ŷ=1)
    • Times: 95th-percentile inference time on the evaluation set.

    Performance KPI

    Combines OP and ML penalized by inference time:

    I_perf = (α_op · exp(-k_c · OP) + α_ml · ML) / (1 + k_t · ln(1 + t))

    Coefficients: α_op = 0.4, α_ml = 0.6, k_c = 1, k_t = 12.

    2. Uncertainty

    Purpose: Evaluate the AI component's ability to express calibrated uncertainty, helping operators assess decision risk.

    Evaluation set: Standard ML evaluation set (20% split).

    Metrics

    • U-OP (Uncertainty Operational Gain): relative virtual gain when using probabilistic outputs vs hard predictions.
    c^U = Σ_k Σ_i Σ_j ŷ_k(j) · cost(i, j, k, k_seam)
UOP = (c^op - c^U) / (c^op - c^op_perfect)
    • U-Calib (Calibration Error): Expected Calibration Error, computed separately on OK and KO subsets to handle class imbalance.
    UCalib = Σ_m (|B_m|/N) · |acc(B_m) - conf(B_m)|

    Class weights: UCalib_OK = 0.2, UCalib_KO = 0.8.

    Uncertainty KPI

    I_U = UOP · (1 - 2 · (UCalib_KO · 0.2 + UCalib_OK · 0.8))

    3. Robustness

    Purpose: Assess model stability under perturbations within the ODD — blur, luminance, rotation, translation. Output should remain invariant as long as perturbations stay inside ODD bounds.

    Evaluation set: Synthetic perturbations applied to a weld-balanced subset of the standard evaluation set, sweeping increasing perturbation levels.

    Perturbation ranges

    Perturbation Range explored Reference
    Rotation [-30°, +30°] (full ODD) — stress-tested in [-10°, +10°] See CLAUDE.md § ODD
    Translation (x, x) with x ∈ [0, 20] pixels (same bound for 1920×1080 and 960×540) evaluation_page.md:177
    Blur Increasing intensity, upper bound set visually (weld no longer visible) evaluation_page.md:179
    Luminance Increasing and decreasing intensity, bounds set visually evaluation_page.md:181

    Metrics

    For each perturbation x ∈ {blur, lum, rot, trans}, the AUC of the ML-performance (precision / FBeta) is computed across perturbation levels:

    r^x = AUC( ML_δ1, ML_δ2, ..., ML_δk )

    Robustness KPI

    Weighted aggregation across the 4 perturbation types:

    I_rob = α_blur · r^blur + α_lum · r^lum + α_rot · r^rot + α_trans · r^trans

    Coefficients: α_blur = 0.3, α_lum = 0.3, α_rot = 0.2, α_trans = 0.2.

    4. OOD Monitoring

    Purpose: Evaluate the model's ability to detect inputs outside the ODD in an unsupervised way — primarily based on the criterion "is the weld sufficiently visible?". The component should return UNKNOWN for OOD inputs.

    Evaluation sets: Two complementary OOD datasets, each balanced with normal samples.

    • OOD_real — built by manual inspection of real images: excessive blur, extreme lighting, visual obstructions hiding the weld.
    • OOD_syn — built by applying strong synthetic perturbations: heavy blur, abnormal luminance, severe color artifacts, Gaussian noise + dead pixels.

    Metrics

    • OOD_real: AUROC on the real OOD evaluation set.
    • OOD_syn: AUROC on the synthetic OOD evaluation set.

    OOD-Monitoring KPI

    I_ood = α_syn · OOD_syn + α_real · OOD_real

    Coefficients: α_syn = 0.3, α_real = 0.7 — real OOD weighted higher because it reflects production conditions.

    5. Generalization

    Purpose: Measure the model's ability to generalize to unseen weld types (C19, C34, C101) that share visual/structural traits with the training seams (c20, c33, c102).

    Evaluation set: Built from welds excluded during training but with similar features.

    Metrics

    • OP_g: Operational performance on the generalization set (same OP formula and cost matrix as Performance).
    • ML_g: ML performance (precision / FBeta) on the generalization set.

    Generalization KPI

    I_gen = α_op · exp(-k_op · OP_g) + α_ml · ML_g

    Coefficients: k_op = 0.05, α_op = 0.4, α_ml = 0.6 (same α weights as the Performance attribute).

    Deferred: Data-Drift handling

    The Data-Drift handling attribute (I_drift) is part of the original challenge evaluation protocol but is deferred for this iteration of the TP.

    For reference, the protocol expects:

    • An operational drift dataset built by applying gradually increasing perturbations to a normal data sequence, with final segments manually labeled as OOD.
    • Two metrics: OP_d (operational performance under drift) and OOD_d (AUROC on the drift-induced OOD subset).
    • KPI formula: I_drift = α_OP · exp(-k_op · OP_d) + α_OOD · OOD_d with α_OP = α_OOD = 0.5, k_op = 0.05.
    • Aggregation weight in the global score: α_6 = 0.05 (lowest among attributes).

    Why deferred: defining a representative drift sequence requires production telemetry over time, which is not in scope for this TP iteration. To be added once an operational data feed exists.

    Aggregation Methodology

    The 5 attribute KPIs above are aggregated into a single trust score using a 6-step pipeline. Notation: α_i, β_i, k_i are weighting / scaling coefficients.

    Step 1 — Compute attribute-specific metrics

    Each attribute is measured by one or several criteria computed on its dedicated evaluation set (cf. sections 1-5).

    Step 2 — Normalize each metric to [0, 1]

    All raw metrics are mapped to [0, 1] (1 = best). Transformations depend on metric nature:

    • Cost-based metrics (OP, OP_g): lower is better → exponential decay exp(-k · x).
    • Bounded metrics (ML, AUROC, calibration): already in [0, 1], optionally rescaled.
    • Time: hyperbolic penalty 1 / (1 + k · ln(1 + t)).

    Step 3 — Aggregate per attribute → Trust-KPI I_X

    For each attribute X, an attribute-specific aggregation function combines its k normalized metrics into a single trust KPI:

    I_X = agg( X_metric_1, X_metric_2, ..., X_metric_k )

    The exact agg function is chosen per attribute (cf. formulas in sections 1-5):

    Attribute Aggregation function
    Performance weighted sum of OP/ML, divided by time penalty
    Uncertainty UOP × (1 - 2·UCalib)
    Robustness weighted sum of 4 AUC scores
    OOD Monitoring weighted sum of 2 AUROC scores
    Generalization weighted sum of OP_g/ML_g (same shape as Performance)

    Step 4 — Piecewise linear rescaling

    Each attribute KPI undergoes a piecewise linear rescaling to align scores with predefined performance and confidence thresholds (α_1, α_2, β_1, β_2):

                ⎧ (β_1 / α_1) · f(x),                                        if 0 ≤ f(x) < α_1
f'(x)  =    ⎨ ((β_2 - β_1) / (α_2 - α_1)) · (f(x) - α_1) + β_1,           if α_1 ≤ f(x) ≤ α_2
            ⎩ ((1 - β_2) / (1 - α_2)) · (f(x) - α_2) + β_2,               if α_2 < f(x) ≤ 1

    Practical effect (calibrated on virtual reference solutions): - A poor solution (e.g. always predicting UNKNOWN) scores around 10 / 100. - A good solution (~3% error rate) scores around 90 / 100 on most attributes.

    Step 5 — Weighted aggregation → final score

    The rescaled attribute KPIs are combined by a weighted mean into the global trust score:

    score = α_1 · I_perf + α_2 · I_U + α_3 · I_rob + α_4 · I_ood + α_5 · I_gen + α_6 · I_drift
    Attribute Weight
    Performance α_1 = 0.30
    Uncertainty α_2 = 0.15
    Robustness α_3 = 0.25
    OOD Monitoring α_4 = 0.20
    Generalization α_5 = 0.05
    Data-Drift (deferred) α_6 = 0.05

    Note: in this iteration, I_drift is not computed — its weight is either redistributed to other attributes or the score is reported on the remaining 0.95 mass (to be decided when the global pipeline is implemented).

    Step 6 — Purpose

    The final score is a single comparable number capturing performance across all trust attributes, designed to:

    • rank competing solutions on a fair basis,
    • highlight which attribute drags the overall score down (via the per-attribute breakdown),
    • align with operational and confidence requirements through the piecewise rescaling.

    KPI Interface (Python)

    The following abstract base class defines how each KPI is implemented in code. Each KPI is a concrete subclass of KPIInterface, exposing a calculate_metric() method that returns one or more numeric scores and a get_kpi_metadata() method that documents its parameters and units.

    from abc import ABC, abstractmethod
from typing import Any, Dict
import random

class KPIInterface(ABC):
    """
    Interface for KPI calculation.
    """

    @abstractmethod
    def calculate_metric(self, data: Any, predictions: Any) -> Dict[str, float]:
        """
        Calculate a specific metric (e.g., F1-score, robustness).
        """
        pass

    @abstractmethod
    def get_kpi_metadata(self) -> Dict[str, Any]:
        """
        Return metadata associated with the KPI.
        """
        pass

class RobustnessKPI(KPIInterface):
    """
    KPI implementation for robustness to flash.
    """

    def calculate_metric(self, data: Any, predictions: Any) -> Dict[str, float]:
        # Simulate calculation
        return {"robustness_score": random.uniform(0.9, 1.0)}

    def get_kpi_metadata(self) -> Dict[str, Any]:
        return {
            "parameter": "flash_intensity",
            "dimension": "percentage"
        }

    Usage example

    from tp_welding.interfaces.kpi import RobustnessKPI

kpi = RobustnessKPI()

# Toy inputs — replace with real evaluation data and model predictions
data = ["sample_1", "sample_2"]
predictions = ["pred_1", "pred_2"]

score = kpi.calculate_metric(data, predictions)
metadata = kpi.get_kpi_metadata()

print(f"Score: {score}")
print(f"Metadata: {metadata}")
# Score:    {'robustness_score': 0.94}
# Metadata: {'parameter': 'flash_intensity', 'dimension': 'percentage'}
