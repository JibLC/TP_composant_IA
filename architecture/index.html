    AI Component Architecture

    This document from Sacha describes the architecture of the AI component for the Welding Quality Detection Challenge (Renault industrial use case).

    Two architectures considered

    This document presents two distinct architectural approaches for the AI component. Each lifecycle phase below (Operation / Training / Evaluation) presents the relevant diagram(s) for both when available.

    Approach Status Core idea
    BASE CASE Project consensus — adopted baseline Pre-processing pipeline (HSL conversion, unblur, un-rotate, flip), clusterize to 6 welding types, routing to one CNN per welding type (C20, C33, C102), MLP-based predictor + ODD detector, multi-timescale online monitoring. Uses ERP metadata (timestamp, weld ID, criticality, material).
    OPTIMIZATION Alternative explored — not adopted 2-stage pipeline: (1) Weld Localizer (YOLOv5n) → bbox_weld; (2) MIL classifier on cropped image_ROI with frozen YOLOv5s-C3CA backbone, attention pooling, weakly-supervised defect localization. Quality measurements (blur, luminosity) on image_ROI only.

    Convention — When "the architecture" is mentioned without further qualifier (here or in other deliverables), it refers to BASE CASE. Any deviation, refinement or alternative must be explicitly attributed to OPTIMIZATION (or to a named new approach).

    The sections below detail each phase. Module-level explanations, design rationale (e.g. Decision: YOLOv5) and the Software Constituents table at the end of the document refer to the OPTIMIZATION approach.

    OPTIMIZATION — Pipeline overview

    The OPTIMIZATION approach implements a 2-stage pipeline designed for weakly-supervised defect detection. Image-level labels (OK / KO) are the only supervision available — no defect bounding-box annotations exist, hence the choice of MIL (Multi-Instance Learning) for defect classification.

    1. Stage 1 — Weld Localization: a lightweight detector finds the welding seam in the input image and outputs a bounding box bbox_weld.
    2. ROI cropping: the image is cropped to bbox_weld, producing image_ROI.
    3. Quality measurements on ROI only: blur and luminosity are computed on image_ROI (not on the full image) so that environmental clutter — background metal parts, secondary welds, shop lighting — does not bias the measurements.
    4. Trustworthy modules (OOD detector, online monitoring) receive both the latent representation and features derived from bbox_weld (position, size, aspect ratio). Geometric drift in the bbox is itself a strong OOD signal (seam moved, occluded, partial framing).
    5. Stage 2 — MIL defect classification on ROI: patches are extracted from image_ROI only; a frozen backbone produces patch embeddings; an attention-based MIL aggregator yields the final OK / KO / UNKNOWN decision and, when KO, a localized bbox_defect derived from the attention map.

    Reference libraries: YOLOv5 (detection + backbone), PUNCC (uncertainty), OODeel (OOD), SAM (Segment Anything — used offline to bootstrap weld pseudo-labels).

    High-level data flow:

    Step Input Module Output
    1 image Weld Localizer (YOLOv5n) bbox_weld
    2 image + bbox_weld ROI Cropper image_ROI
    3 image_ROI Blur Measure / Luminosity Measure blur_ROI, luminosity_ROI
    4 image_ROI MIL Bag Builder patches
    5 patches Backbone YOLOv5s-C3CA (frozen) latent embeddings
    6 latent MIL Aggregator (attention pooling) bag score + attention map
    7 bag score Predictor + UQ + OOD OK / KO / UNKNOWN + scores
    8 attention map Defect Localizer bbox_defect (if KO)
    9 bbox_weld, blur_ROI, luminosity_ROI, OOD score Online Monitoring drift indicators

    Intermediate artefacts

    Artefact Producer Consumer(s) Purpose
    bbox_weld Weld Localizer ROI Cropper, OOD Detector, Online Monitoring Locates the weld; geometric drift signal
    image_ROI ROI Cropper Blur/Lumi Measurers, MIL Bag Builder Restricts processing to the relevant region
    blur_ROI Blur Measure Online Monitoring Quality signal on the weld area
    luminosity_ROI Luminosity Measure Online Monitoring Quality signal on the weld area
    attention_map MIL Aggregator Defect Localizer Per-patch importance weights
    bbox_defect Defect Localizer Output Interface Localized defect (KO only)

    Module-by-module notes (OPTIMIZATION):

    • Preprocessor: minimal — resize to a canonical size and normalize pixel intensities. No quality measurement here (deferred to post-ROI).
    • Weld Localizer: YOLOv5n outputs the weld bbox. Trained offline (see Training section). Single forward pass, ~10 ms on GPU.
    • ROI Cropper: pure utility (cv2 + small padding). Adapts the canonical size of image_ROI to MIL bag builder constraints.
    • Blur / Luminosity Measure: computed on image_ROI only. The blur_level and luminosity_level fields in the dataset metadata correspond to full-image measurements; the monitoring values used here are the ROI-restricted versions.
    • MIL Bag Builder: extracts a fixed grid of patches (or sliding window with overlap) from image_ROI. Each patch becomes one MIL "instance".
    • Backbone: YOLOv5s-C3CA, frozen weights from ImageNet pre-training. Outputs a feature vector per patch.
    • MIL Aggregator: attention-based pooling (Ilse et al. 2018) that learns per-patch attention weights and aggregates instance embeddings into a bag-level embedding.
    • Predictor: classification head on the bag embedding → OK or KO. Returns UNKNOWN if the conformal prediction set (PUNCC) is empty or if the OOD score crosses a threshold.
    • UQ (PUNCC): conformal prediction calibrated offline — provides confidence sets with formal coverage guarantees.
    • OOD Detector (OODeel): receives both the latent representation and geometric features of bbox_weld (position, size, aspect ratio relative to per-(seam, resolution) reference). Geometric drift = early OOD signal.
    • Online Monitoring: aggregates blur_ROI, luminosity_ROI, bbox_weld features and OOD score into rolling-window indicators of operational drift.
    • Defect Localizer: when KO, picks the patch(es) with the highest MIL attention weight and projects their position back into image_ROI coordinates → bbox_defect. Weakly-supervised localization.

    Training notes (OPTIMIZATION):

    • Pseudo-labelling step (offline): SAM is run once on the dataset to generate weld masks; bounding boxes are extracted and stored as bbox_weld_pseudo. As fallback when SAM fails (low-quality mask or weld not found), a static ROI per (seam, resolution) is used (the camera viewpoint is fixed per seam, so a per-group default ROI is reasonable).
    • Stage 1 training: YOLOv5n is fine-tuned from ImageNet weights on (image, bbox_weld_pseudo) pairs. Single-class detection task ("weld").
    • Stage 2 training: the YOLOv5s-C3CA backbone stays frozen; only the MIL attention pooling module and the classifier head are trained. Loss adapted to the 97.8% / 2.2% OK/KO imbalance (focal loss or class weights).
    • Calibration sets are kept disjoint from training to preserve PUNCC's conformal coverage guarantees and OODeel's validation.

    Evaluation notes (OPTIMIZATION):

    • Stage 1 metric (IoU): bbox_weld evaluated against a manually-curated reference ROI on a sample of test images. Acceptance threshold typically IoU ≥ 0.7.
    • Stage 2 + trust attributes: 5 of the 6 challenge attributes are computed (Performance, Uncertainty, Robustness, OOD Monitoring, Generalization). Data-Drift is deferred for this iteration of the TP — see docs/kpi/index.md § Deferred for the rationale.
    • Aggregation: per-attribute KPIs are normalized to [0, 1], rescaled piecewise linearly, then combined into a single trust score with the official weights (also documented in docs/kpi/index.md).

    Decision: YOLOv5 — still relevant? (OPTIMIZATION)

    Applies to the OPTIMIZATION approach. The BASE CASE uses a different backbone strategy (one CNN per welding type, not specified as YOLOv5).

    Verdict: yes, but with a clarified role on two distinct models.

    Stage 1 — Weld Localizer: YOLOv5n

    • ~1.9M parameters, ~10 ms inference on a modern GPU. Fits the latency budget (median < 200 ms total per KPI Performance).
    • The welding seam is a well-delimited object on a contrasted background — a lightweight detector is sufficient; no need for transformer-class capacity.
    • Cameras have a fixed viewpoint per seam, so the bbox distribution is restricted → fast convergence, easy generalization.
    • Pseudo-labels are generated offline with SAM (no inference-time cost), then YOLOv5n is fine-tuned from ImageNet weights.

    Stage 2 — Defect Classification: YOLOv5s-C3CA backbone (frozen) + MIL head

    • The C3CA blocks integrate Coordinate Attention, which preserves spatial information after pooling → useful for an attention-based MIL aggregator that needs to localize defects from patch importance.
    • The s variant is sufficient because the input is already cropped to image_ROI (smaller than the full image), reducing the parameter count needed.
    • YOLOv5 is not used in detection mode here: the dataset only provides image-level labels (OK / KO), so a supervised detector for defects is impossible. The MIL paradigm is the appropriate response to weak supervision.
    • Defect localization (bbox_defect) is done via the MIL attention map (Ilse et al. 2018), not via a YOLO head — no defect bbox supervision is available.

    Why not a different architecture?

    • Vision Transformer + RoI pooling: more capacity but requires more data and inference time, both scarce. Overkill for a binary classification on ~22k images.
    • EfficientNet / ConvNeXt backbones: viable alternatives but lose the Coordinate Attention benefit; would be a candidate if YOLOv5s-C3CA shows poor MIL attention quality during evaluation.
    • End-to-end 1-stage detector (e.g. YOLOv5 trained on full image with weld + defect classes): impossible without defect bboxes.

    Module Implementation Role
    Preprocessor cv2 + numpy Resize to canonical size, normalize pixel intensities
    Weld Localizer YOLOv5n fine-tuned on SAM pseudo-labels image → bbox_weld
    ROI Cropper cv2 + padding utility image + bbox_weld → image_ROI

    Luminosity Measure image_ROI.mean() (or HSV-V channel) → luminosity_ROI
    MIL Bag Builder grid or sliding window over image_ROI → patches
    Backbone YOLOv5s-C3CA (frozen, ImageNet pre-trained) patches → latent embeddings
    MIL Aggregator Attention pooling (Ilse et al. 2018) latent → bag embedding + attention map
    Predictor Classification head + UNKNOWN thresholding bag embedding → OK / KO / UNKNOWN
    Defect Localizer argmax on attention map + bbox projection attention map → bbox_defect (KO only)
    Uncertainty Quantifier PUNCC (conformal prediction) bag embedding → confidence set
    OOD Detector OODeel + geometric features of bbox_weld latent + bbox → OOD score
    Online Monitoring rolling-window aggregator blur_ROI, luminosity_ROI, bbox_weld, OOD score → drift indicators
